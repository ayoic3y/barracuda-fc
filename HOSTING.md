# Как выложить сайт в интернет и обновлять его

Проект уже подготовлен: есть git-репозиторий, файл `.gitignore`, кнопка пересборки
`build.cmd` и настройка автодеплоя `.github/workflows/pages.yml`.

Главное правило: **источник правды — папка `_src`**. Папка `barracuda-fc` собирается
из неё автоматически, руками её править не нужно (перезапишется при следующей сборке).

---

## Шаг 0. Проверить, что всё собирается

Двойной щелчок по **`build.cmd`** — сайт пересоберётся и откроется в браузере.
Если Python не установлен: скачайте с python.org и при установке отметьте
«Add python.exe to PATH».

---

## Вариант A (рекомендую): GitHub + GitHub Pages с автодеплоем

Один раз настраиваем — дальше сайт обновляется сам после каждого обновления файлов.

1. Зарегистрируйтесь на github.com и создайте **новый пустой репозиторий**,
   например `barracuda-fc` (без README и без .gitignore — они уже есть у нас).
2. В папке проекта откройте терминал (в Проводнике: правой кнопкой по папке →
   «Открыть в терминале») и выполните **одну строку**, подставив свой логин:

   ```powershell
   git remote add origin https://github.com/ВАШ-ЛОГИН/barracuda-fc.git
   git push -u origin main
   ```

   При первом пуше GitHub попросит войти (откроется браузер) — это нормально.
3. В репозитории: **Settings → Pages → Source: GitHub Actions**.
4. Через 1–2 минуты сайт будет доступен по адресу
   `https://ВАШ-ЛОГИН.github.io/barracuda-fc/`

Дальше цикл обновления такой: правите `_src/data.py` → `build.cmd` (проверить локально) →
`git add -A` → `git commit -m "новость"` → `git push`. Сайт пересобирается на GitHub
сам, локальный Python при этом уже не обязателен.

---

## Вариант B: Netlify или Cloudflare Pages (тоже с автодеплоем)

При подключении репозитория укажите настройки сборки:

* Build command: `python _src/generate.py`
* Publish directory: `barracuda-fc`
* Python version: 3.12 (переменная окружения `PYTHON_VERSION=3.12`)

После этого каждый push автоматически публикует новую версию.

---

## Вариант C: обычный хостинг по FTP (без Git)

Каждый раз после пересборки заливайте **содержимое** папки `barracuda-fc`
в корень сайта на хостинге (по FTP или через файловый менеджер панели).
Это самый простой путь, но правки нужно заливать руками после каждой сборки.

---

## Как отдавать правки мне

Пишите прямо в чат: «добавь новость такую-то», «поменяй счёт матча», «обнови таблицу».
Я правлю `_src/data.py`, пересобираю сайт и (если настроен Git) готовлю коммит;
пуш делаете вы одной командой — или, если репозиторий уже настроен и есть доступ,
я отправляю изменения сам.

## Если что-то сломалось

* Посмотреть, что изменилось: `git status` и `git diff`
* Отменить все незакоммиченные правки: `git checkout -- .`
* Вернуть прошлую версию целиком: `git log --oneline`, затем `git checkout <хеш> -- .`
* Ошибка при сборке чаще всего означает пропущенную запятую или кавычку в `_src/data.py` —
  текст ошибки указывает строку.
